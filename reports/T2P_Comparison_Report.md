## 一、相同/保留部分

以下模块在两版之间基本一致，新版在旧版基础上进行了继承和局部优化：

### 1.1 题目生成管线（Problem Generation Pipeline）

| 组件 | 旧版 | 新版 | 变化 |
|------|------|------|------|
| PromptBuilder | 双模式提示词构建 | 相同 | 无变化 |
| 生成模式 | Drill + Exam（锚点+关联知识点融合） | 相同 | 无变化 |
| 题型支持 | 计算 / 选择 / 填空 | 相同 | 无变化 |
| 难度等级 | 1-5 | 相同 | 无变化 |
| 自修复重试 | 最多 3 次，AI 反馈注入 healing_block | 相同（`_generate_with_retry_logic`） | 无变化 |
| 输出 JSON Schema | id, topic, problem_statement, solution, scaffolding, integration_analysis | 相同 | 无变化 |

### 1.2 质量评估体系（QualityEvaluator）

| 维度 | 旧版权重 | 新版权重 | 变化 |
|------|---------|---------|------|
| 数学逻辑 | 35% | 35% | 相同 |
| 结构完整性 | 10% | 10% | 相同 |
| 支架质量 | 15% | 15% | 相同 |
| 教学适配 | 15% | 15% | 相同 |
| 概念融合 | 15% | 15% | 相同 |
| 原创性 | 10% | 10% | 相同 |

通过阈值两版也完全一致：Drill 模式总分 ≥ 60 + 数学正确 + 结构 ≥ 75；Exam 模式额外要求融合 ≥ 50。

### 1.3 后处理管线（PostProcessor）

8 步 LaTeX 清洗管线、Sentence-Transformer 语义去重（阈值 0.85）、JSON 容错解析——两版完全一致。

### 1.4 自适应学习路径（UserSession）

EMA 掌握度算法（`new = old × 0.4 + score × 0.6`）、Level 晋升机制（L1→L2→L3）、85% 阈值自适应推荐——两版完全一致。

### 1.5 前端架构

Next.js + React + Tailwind CSS + KaTeX + react-signature-canvas + Recharts——技术栈一致。题目展示、支架展开/收起、手写画布、图片上传、批改结果展示、学习仪表盘（Radar + Bar）——功能一致。

### 1.6 429 限流保护

多层冷却策略（请求级重试 90s、生成级阶梯退避、批量级延迟）——两版设计思路一致，仅参数根据 LLM 厂商不同有所调整。

## 二、关键差异

### 2.1 多智能体系统（最核心差异）

| | 旧版 | 新版 |
|------|------|------|
| 多 Agent | **无** | **4 个 Agent + 2 套架构** |
| Agent 通信 | 不存在 | 结构化 Message（8 种类型） + MessageBus |
| Agent 并发 | 不存在 | asyncio 并发执行 |
| 前端实时监控 | 无 | SSE 实时 Agent 对话流 |
| 多智能体 UI | 无 | 独立的多智能体合成面板 |

旧版报告中完全没有多智能体系统的任何描述。其"未来工作"部分提到"multi-model collaboration"指的是使用多个不同模型（如开源模型 + 商业模型）来降低成本，而非多 Agent 协作。

新版是旧版的**重大架构升级**——在保留原有单管线的基础上，新增了两套多智能体架构：
- **V1（`src/agents/`）**：4 个 Agent 按固定流水线执行（Synthesizer → Scaffolder → Reviewer → Curator）
- **V2（`src/multi_agent/`）**：4 个自治 Agent 通过 MessageBus 进行直接消息通信，自主决策协作

### 2.2 LLM 供应商变更

| | 旧版 | 新版 |
|------|------|------|
| 模型 | Google Gemini 2.5 Pro | DeepSeek V4 Pro |
| 部署方式 | Google Vertex AI（云端） | DeepSeek API（OpenAI 兼容） |
| API 风格 | Vertex AI SDK | `openai` Python 包 |
| 429 策略 | 同一冷却逻辑 | 同一冷却逻辑（参数适配） |

LLM 供应商从 Google 切换为 DeepSeek，但 OpenAI 兼容的 API 接口设计降低了切换成本。Prompt 模板、评估维度、后处理管线均未因模型变更而调整，说明系统设计具有较好的模型无关性。

### 2.3 OCR 模块

旧版报告中**未提及独立的 OCR 模块**——"AIMentorIntelligentGrading" 部分提到支持手写图片上传，但未说明 OCR 转录层。

新版有独立的 `src/ocr.py` 模块，使用 DeepSeek Vision 模型进行手写数学 → LaTeX 转录，并将转录文本传递给审查 LLM（成功时切换为 text-only 模式以节省 token）。

### 2.4 前端批改结果展示

| | 旧版 | 新版 |
|------|------|------|
| OCR 转录展示 | 无 | **有**（学生可确认识别是否正确） |
| 自然书写指引 | 无 | **有**（明确说明"写数学公式，不要写 LaTeX"） |
| 批改结果 | 逻辑分数 + 错误分析 + 导师反馈 + 下一步提示 | 相同 + OCR 转录 |

新版在前端增加了 OCR 转录结果展示和"请自然书写数学"的 UI 指引文字，改善了学生体验。

### 2.5 系统端点

| 端点 | 旧版 | 新版 |
|------|------|------|
| `/` | ✓ | ✓ |
| `/topics` | ✓ | ✓ |
| `/generate` | ✓ | ✓ |
| `/audit` | ✓ | ✓ |
| `/user/login` | ✓ | ✓ |
| `/user/progress/{user_id}` | ✓ | ✓ |
| `/user/record` | ✓ | ✓ |
| `/synthesize` | **无** | ✓（V1 多智能体流水线） |
| `/synthesize-v2` | **无** | ✓（V2 消息驱动多智能体） |
| `/synthesize-v2/stream` | **无** | ✓（SSE 实时流） |

新版新增了 3 个多智能体相关端点。

### 2.6 LLM 调用效率

旧版无多 Agent 架构，题目生成通过单管线完成，无 Agent 层的 LLM 调度开销。

新版 V2 多智能体系统将每道题的 LLM 调用从 8-10 次（V1）优化到 4-5 次（V2），核心优化是消除了"Agent 调 LLM 做路由决策 → 工具再调 LLM 做实际工作"的双层浪费。

### 2.7 实验评估

| | 旧版 | 新版 |
|------|------|------|
| 样本量 | 10 道题 | 功能验证（无独立实验） |
| 评估方法 | 内置 QualityEvaluator 审计打分 | 功能连通性测试 |
| 数学逻辑得分 | 10 题全满分（100.0） | — |
| 综合质量 | 平均 81.1，100% 通过率 | — |
| 支架策略得分 | 平均 43.5（偏低，已识别为优化方向） | — |
| 概念融合得分 | Drill 模式平均 13.0（符合预期） | — |
| 原创性 | 10 题全满分 | — |

旧版报告包含定量的实验分析（虽然样本量较小），新版报告以功能验证为主，缺少独立的实验评估数据。旧版的实验结果实际上直接适用于新版，因为题目生成管线和质量评估器在两版之间完全一致。

## 四、综合评价

### 旧版优势
1. **实验数据完整**：包含 10 道样本的定量分析，各维度得分有明确数据
2. **截图丰富**：16 张系统截图直观展示各功能模块
3. **工程细节充分**：Vertex AI 429 保护、自修复机制的描述详细

### 新版优势
1. **多智能体架构**：从无到有，且实现了两套架构（流水线 + 消息驱动），是质的飞跃
2. **LLM 调用效率**：V2 约 50% 的 LLM 调用减少
3. **实时监控**：SSE 流式展示 Agent 对话
4. **用户体验改善**：OCR 转录展示、自然书写指引
5. **模型无关性**：从 Gemini 切换到 DeepSeek 仅需改 API 配置

### 新版不足
1. **缺少独立实验**：未像旧版那样对生成题目做定量质量分析
2. **无系统截图**：报告以文字描述为主
3. **多智能体评估缺失**：V1 vs V2 对比停留在架构层面，缺少端到端性能数据
